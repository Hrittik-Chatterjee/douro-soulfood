# i18n

**Full detail: `docs/i18n.md`.** This file is only the pointer.

`LOCALE_REGISTRY` in `src/lib/i18n/locales.ts` lists every locale (`de-AT` live; `en`/`zh`/`pt` `planned`, each with a `blockedBy` reason). `LIVE_LOCALES` is derived from it — the ONLY thing that gates a locale into `astro.config.mjs`'s `i18n.locales`, the sitemap's `i18n.locales` map, `LanguageSwitcher.astro`'s render, and `t()`'s fallback chain. Flip one `status` field; nothing else changes.

`astro.config.mjs` has real `i18n` + sitemap `i18n` config, not a stub — `routing.prefixDefaultLocale: false`, no `fallback` set (a fallback would serve German at `/en/*`, which must never happen). Verified against installed `@astrojs/sitemap@3.7.2`: alternates self-suppress via that package's own `links.length <= 1` guard, so a one-locale map structurally cannot emit `<xhtml:link>` — not disabled, nothing to pair with yet.

`src/lib/nav.ts` de-duplicates the primary 4-item nav (was independently hand-typed in `NavBar.astro` and `Footer.astro`); `src/lib/i18n/ui.ts` + `messages/de-AT.ts` hold chrome strings that must stay code, not Keystatic (a client editing CMS copy must not be able to break an `aria-label`) — currently covers the mobile drawer's open/close labels, which used to be hardcoded German inside an inline `<script>` (a CSP-hash cost per locale if left that way).

`pnpm check:i18n` fails the build if a live non-default locale is missing keys — proven fail-closed, not just asserted.

**Not done**: no `en`/`zh`/`pt` pages, `LanguageSwitcher` not mounted anywhere yet (renders null with 1 locale — nothing to mount for). Legal pages (`/impressum`, `/datenschutz`) stay German-only **permanently** — business/legal decision, not a gap.
